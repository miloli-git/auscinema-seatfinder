## Method notes

- Chain sites (Event, Hoyts, Reading, Village) Cloudflare-challenge headless browsers — all verified in headed mode.
- Cold load = fresh browser context with no prior cookies/storage, exactly how a real user arrives from a shared link.
- Reading's `bookingUrl` is generated by the ingester adapter at ingest/refresh time and cached in Postgres (`sessions.booking_url`), not computed live per-request. After the 2026-07-05 deploy (PR #68 merged to main), newly-refreshed rows immediately produce the corrected `/cinemas/{cinemaSlug}/sessions/{sessionId}/{VistaFilmId}` form; older cached rows retain the pre-fix `/sessions/{id}/{slug}` form until the rolling refresh worker (budget-limited, ~60-70 sessions/tick) reaches them. Ran several manual `refresh --once` cycles post-deploy to accelerate rollover, then extracted and cold-load-verified a freshly-refreshed Reading URL directly from the live app UI. Full cache backfill across all ~530 cached Reading sessions completes gradually over the following hours as the normal refresh loop cycles through — not a code defect, just cache turnover.
