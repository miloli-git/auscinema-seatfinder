# Research brief: portfolio layouts for presenting design / UI work

You are a senior product-design / design-portfolio expert. Do live web research (use web_search)
and return a practical, opinionated, well-cited report. This is for a REAL decision, not an essay.

## Who this is for
A builder who is strong on backend / AI-agent orchestration but NOT a trained frontend/visual
designer. He has built a public open-source side project ("AusCinema Seat Finder" - finds the cinema
seat actually worth sitting in, scores seat quality, hands off to official booking). As a portfolio
exercise he produced SEVEN whole-page UI directions, several grounded in design systems he extracted
from live sites (Locomotive, Glossier, Sydney Opera House) via automated scraping, plus one rendering
a REAL auditorium layout from real data. He currently presents them on a basic 2-column "comparison
grid" gallery page with iframes. He does NOT like that comparison page and wants a better way to
present this work in a portfolio.

His differentiator is process and systems-thinking (extracting real design systems, using real data),
not pixel polish. The portfolio should play to that.

## What to research and answer
1. **How strong design/UI portfolios present multi-direction exploration work.** Patterns for showing
   "I tried N directions and converged" without it looking like an unfinished dump. Case-study
   structure vs gallery vs interactive showcase.
2. **Concrete layout / IA patterns** to replace a plain comparison grid. Give 3-5 named, described
   patterns (e.g. narrative case-study scroll, before/after, decision-log, side-by-side toggle,
   annotated hero + supporting grid, live interactive switcher). For each: when it works, structure,
   and rough section order.
3. **What design hiring managers / design leads actually look for** in a portfolio case study
   (process, rationale, constraints, outcomes) - cite sources/opinion pieces.
4. **How a non-designer / AI-native builder should frame design work** so the extraction-method and
   real-data angle reads as a strength, not as "I'm not really a designer."
5. **Reference examples** - link to specific well-regarded design portfolios / case studies and say
   what each does well that is worth stealing.
6. **Tactical specifics** for a static, single-page, self-hosted (GitHub Pages) showcase: structure,
   above-the-fold, navigation, how to handle 7 live mocks, mobile, performance.

## Output format (write to stdout as markdown)
- **BLUF** (3-5 bullets): what to actually do.
- **Recommended structure** for HIS page (concrete section-by-section outline he can build).
- **Pattern catalogue** (the 3-5 patterns, each with when/structure).
- **What to steal** (reference portfolios with one-line takeaways + links).
- **Pitfalls** to avoid.
- **Sources** (links).
Keep it concrete and buildable. No filler. No em dashes.
